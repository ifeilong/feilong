一、三条主线

1. 3.0.x —— 一次性的破坏性大重构

3.0.0 单版本 140 处变更，是整个历史里最大的一次：包名统一（com.feilong.net.httpclient4 → com.feilong.net.http、com.feilong.json.jsonlib → com.feilong.json）、模块重排（feilong-velocity → feilong-template、多个 feilong-xml-* / feilong-json-* 子模块删除合并）、大量类直接删除（DomParser、KeyBuilder、MoneyUtil、ColorUtil、ImageUtil、ProcessUtil…）、升级到 JDK 8。

随后的 3.0.2 – 3.0.10 是一条「把第三方库打散进项目 + 转成 optional」的收尾流水线：commons-codec / commons-net / commons-compress / commons-digester3 / ognl / slf4j-api / xstream 依次被「打进项目组」，同时补 source 与 javadoc 附件。

2. 3.1 – 3.5 —— 工具类「长肉」期

这是 feilong 的主力扩张阶段，几乎每个版本都在往核心工具类里加方法：CollectionsUtil、ObjectUtil、MapUtil、StringUtil、DateUtil、ConvertUtil、ThreadUtil、HttpClientUtil、RequestUtil。特点是小步高频（3.3.x 有 10 个补丁版本），每次 1–10 个方法，签名越来越长（..., Class<T>、..., boolean 这类显式参数）。

3. 4.0 – 4.5 —— 反射式 API 退场，Function 上位

4.0.0 出现第一个 Function 版本的重载（CollectionsUtil.getPropertyValueList(Collection, Function)），4.5.2 lambda 化大爆发，4.5.5 补上 removeDuplicate(Collection, Function)，4.5.6 一次性把 13 个属性名(反射)方法标记 @Deprecated——至此「弱化反射式 API」成为公开的路线。

同期另一半精力转向发布工程：模块聚合成一个 feilong jar、shade、gpg/nexus 发布、javadoc 审计、README 英文化、插件批量升级。

4.4.0 还有一个小转向值得单独记：引入日志上下文体系（CustomFixedContextLogCreator + SPI），并把工具类的私有构造器、日志声明分别统一到 Lombok 的 @NoArgsConstructor(access = PRIVATE) 与 @Slf4j，属于「代码形态统一」的一步。

三、十个转折点

版本为什么重要
3.0.0一次性的架构重置：包名、模块、JDK 基线、依赖策略全在这里定下来；之后的版本都在这个骨架上长
3.0.2 – 3.0.3「把第三方库打散进项目」的执行期；同时补上 source/javadoc 附件（#222），这是中央仓库体验问题的起点
3.1.0单版本 40 处变更，机器人能力（钉钉）+ ObjectUtil.equalsAny + 一大批插件升级同时落地
3.2.0把 log4j 换成 log4j2；ServletContextUtil.EXCLUDE_KEYS 从硬编码改成配置文件
3.4.0安全驱动的删依赖：删 feilong-lib-xstream、xstream 转 optional（#40/#320 XStream 漏洞）
4.0.0反射→Function 的起点；httpclient 并入 feilong-lib（包名变成 com.feilong.lib.org.apache.http.*，后续所有日志配置坑都源于此）
4.0.3 / 4.0.6ThreadUtil 从「sleep 工具」升级成「分片并发执行框架」，并开始淘汰旧签名（4.0.6 一次标 4 个 deprecated）
4.5.0文档从 oschina 迁到 gitbook；catch exception → catch throwable（LogContextExecutor）
4.5.2lambda 化正面战场：groupBy/select/find/getPropertyValueMap 的 Function 版本集中落地；同时 6 条 @deprecated 计划以删除线标注（未落地）
4.5.613 个属性名(反射)方法一次性 @Deprecated，宣告路线完成；同版本补齐 defaultZero 金额版、周边界、splitByExistId、HttpRequest.builder()、zip slip 修复、javadoc 全量审计

六、几个容易记错的事实

  1. 里程碑编号 ≠ 版本号：milestone/49 = 4.4.0、milestone/53 = 4.5.4、milestone/54 = 4.5.5、milestone/55 = 4.5.6。早期版本（3.x、4.0–4.3）的说明文件里没有记录 milestone。
  2. 标题与实际实现不一致的先例：4.5.5 的 #855 标题写的是「改造成 removeCollections」，但代码里方法名仍是 removeAll，只是加了可变参数。
  3. 删除线 ≠ 已发布：4.5.2 的说明里 6 条 @deprecated 计划是一条删除线状态，当次没有落地；对应的废弃动作直到 4.5.6 才集中做。
  4. 文档量级差异极大：3.0.0（140 处）与 4.5.6（38 处）是两次大版本；中间的 3.2.3、3.0.1 只有 1 处变更。读历史时别按「版本数」判断工作量。
  5. formatDuration 是个反面案例：3.5.1 因为「自身耗时长」被废弃（#572 #573），4.0.0 又把内部调用全部改成毫秒（#586）——一个 API 因为性能原因退场，代码里还得再清一轮。
